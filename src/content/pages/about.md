I build things for the web — mostly the unglamorous parts that make everything else possible. Build pipelines, type-safe APIs, the internal tools nobody notices until they break. I like software that gets out of the way.

Most of my time these days goes into developer experience: faster feedback loops, fewer footguns, documentation that answers the question you actually had. I think a lot about the gap between "it works" and "it works and the next person can maintain it without cursing my name."

I came up writing a bit of everything — backend services, scrappy frontends, the occasional shell script that outlived every system it was supposed to be temporary for. That generalist streak stuck. I'm happiest moving between layers of a stack rather than staying fenced into one.

Outside of work I read more RFCs than is strictly healthy, tinker with static site generators (this one included), and keep a running list of tools I mean to try and never do. This site is itself one of those tinkering projects — an experiment in treating a personal site's markdown source as part of the design, not just the input to it.

If you want to see what I'm currently building, [projects](/projects) has the running list. If you want to see what didn't make the cut, [experiments](/experiments) is the more honest version of that list.
